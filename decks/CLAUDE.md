## canonical/<type>/

The master for a deck type. Contents:
- `deck.yaml` — the composition: `title`, `type`, `vars` (deck_footer,
  cover_meta), optional `allowed_entitlements`, ordered `slides` (library ids).
- `index.html` — GENERATED by `tools/assemble-deck.py`. Never hand-edit it; edit
  the fragments/deck.yaml and re-assemble.
- `<type>.pdf` — committed.

The canonical "best version" is a git tag `canonical/<type>@vN`, set in Edit mode
when Floris declares it. Changing a canonical is `/edit-canonical`.

## variants/<slug>/

A frozen, shipped deck, produced by `/new-deck`. Folder name is
`YYYY-MM-DD_<purpose-or-client-slug>`. Contents:
- `brief.md` — the intake answers + approved plan (this deck's contract).
- `deck.yaml` — its composition (+ `allowed_entitlements` if cleared for named
  customers), and any local slide overrides under `slides/<id>/slide.html`.
- `index.html` — the assembled, self-contained deck.
- `<slug>.pdf` — committed.
- `manifest.yaml` — provenance: source canonical + per-slide commit hashes.

## Frozen means frozen

A variant is a snapshot in time. Improving a canonical later NEVER changes a
variant already made — its `index.html` is standalone and is not regenerated. If a
variant should adopt an improvement, that is a fresh `/new-deck` run.

## Build & verify

```
python tools/assemble-deck.py decks/<path>
.\tools\build-pdf.ps1 -Deck decks\<path>
python tools/verify-deck.py decks/<path>
```
Then do the human visual per-slide pass (CLAUDE.md at repo root).
